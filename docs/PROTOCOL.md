# Сетевые протоколы GS Multiplayer

Три независимых слоя. Ни один не зависит от Minecraft — они покрываются юнит/интеграционными тестами.

```
Minecraft (TCP)                      Minecraft (TCP)
   │ StreamBridge                       │ StreamBridge
   │ ReliableLink (SACK/UDP)            │ ReliableLink
   │ Puncher / RelayAccess              │ Puncher / RelayAccess
   └──── UDP ───────────────────────────┘
        напрямую (P2P) или через relay
```

## 1. Соединение (negotiation)

Через signaling (см. [SERVER_API.md](SERVER_API.md)) обмениваются:

1. `signal {data: {t:"cand", cands: ["ip:port", ...]}}` — списки кандидатов.

Кандидаты:

- **host** — все локальные IPv4-адреса интерфейсов + loopback (пара `ip:port` одного UDP-сокета);
- **srflx** — внешний адрес по STUN (RFC 5389, XOR-MAPPED-ADDRESS), серверы по умолчанию:
  `stun.l.google.com:19302`, `stun1.l.google.com:19302`, `stun.cloudflare.com:3478`.

2. Оба игрока одновременно (host и guest равноправны) шлют UDP-пробы:

```
Puncher: 0x47 | ver=1 | 6 байт кода комнаты | u32 sessionId | role (1=probe, 2=ack)
```

Проблет все кандидаты оппонента: 3 раунда по 150 мс, далее 300 мс, до таймаута
(по умолчанию 6 с). Первая пришедшая проба/ack фиксирует рабочую пару адресов;
в течение 800 мс победитель продолжает слать ack, чтобы и второй пир сошёлся.

3. Успех → транспорт **P2P**. Таймаут → через signaling запрашивается
   `relay.token`, пир регистрируется на relay → транспорт **RELAY**.

## 2. Relay (резервный транспорт)

UDP-датаграммы, бинарные:

| Magic | Формат | Назначение |
|---|---|---|
| `0x52` reg | `0x52 \|\ <utf8 json {token}>` | регистрация пира (с ретрансмиссией ≤6 раз) |
| `0x53` ack | `0x53 \|\ <utf8 json>` | ответ: `{t:"ok",peerId,peersInRoom}` или `{t:"error",code:"BAD_TOKEN"}` |
| `0x44` data | `0x44 \| u32 destId \| payload` | payload пересылается адресату дословно |
| `0x4B` ka | `0x4B` | keepalive (продлевает сессию, TTL 120 с) |

- Токен: `<roomCode>.<peerId>.<expiryMs>.<hmac-base64url>`, HMAC-SHA256 от общего секрета.
- Relay без состояния: таблица `peerId → addr:port`, пересылка без чтения payload.
- payload — это пакеты ReliableLink (до ~1114 байт); датаграммыrelay не фрагментируются.

## 3. ReliableLink — надёжный упорядоченный канал

Заголовок (big-endian, 14 байт) + payload (≤1100):

```
u8  version = 1
u8  flags   (bit0 ack-only, bit1 ping, bit2 pong, bit3 fin)
u32 seq     — номер отправки (у ack/ping/pong/fin seq=0)
u32 ack     — кумулятивно: все данные с seq <= ack доставлены приложению
u32 ackBits — бит i-1: "пакет ack+i лежит в reorder-буфере получателя"
```

Механика:

- Отправка: окно до 64 неподтверждённых, очередь до 128; `send()` блокируется при полном окне (таймаут 15 c).
- Приём: in-order доставка приложению; пришедшие вперёд — в reorder-буфер (до 256); дубликаты и «далёкое будущее» — дроп.
- Подтверждения: каждое получение данных индуцирует ack-only пакет (кумулятивный ack + SACK-биты по reorder-буферу).
- Ретрансмиссия: тик 40 мс; если старейший НЕ-удерживаемый пакет старше RTO (150..2500 мс, из SRTT: `2·SRTT+80`, старт 400 мс) — пересылаются все не-удерживаемые пакеты. Пакеты, помеченные SACK-битом как «held», не ретранслируются — они уже у получателя.
- Выход из строя: старейший не-удерживаемый пакет старше 30 с → `connection lost`.
- RTT: ping/pong каждые 4 с (payload = метка времени); Karn: образцы только от пакетов без ретрансмиссий и при незанятом окне.
- FIN шлётся тремя копиями (он ненадёжен); закрытие детектируется и по таймауту.
- Потери (диагностика): `retransmits / (sent + retransmits)` за последние 5 с.

Корректность: кумулятивный ack — единственное условие удаления пакета; SACK-биты
только экономят ретрансмиссии. Старейший не-удерживаемый пакет — всегда ровно та
дыра, которую ждёт получатель, поэтому потери не приводят ни к пропускам, ни к
залипаниям.

## 4. StreamBridge — мост Minecraft TCP ↔ туннель

Кадры внутри ReliableLink (после 14-байтного заголовка):

```
u8 streamId | u8 op | u16 len | payload(len)
op: 0=OPEN, 1=DATA, 2=EOF, 3=RST
```

- **Гость** слушает `127.0.0.1:<эпhemeral>`; каждое принятое TCP-соединение = новый stream (OPEN хосту). Minecraft подключается сюда как к обычному серверу (`ConnectScreen` на `127.0.0.1`).
- **Хост** на OPEN открывает TCP к интегрированному серверу (`127.0.0.1:25575`) и перекачивает байты в DATA/EOF.
- Чанки ≤1000 байт; потоков максимум 255 (по одному на подключение гостя).

## 5. Лимиты и параметры

| Параметр | Значение | Где |
|---|---|---|
| MAX_CHUNK | 1100 байт | ReliableLink |
| окно неподтверждённых | 64 | ReliableLink |
| reorder-буфер | 256 пакетов | ReliableLink |
| RTO | 150..2500 мс, адаптивный | ReliableLink |
| таймаут punch | 6 с (config) | P2pTunnel |
| TTL relay-сессии | 120 с без пакетов | server relay |
| TTL relay-токена | 2 ч | server tokens |
| STUN timeout | 2.5 с на сервер | StunResolver |
